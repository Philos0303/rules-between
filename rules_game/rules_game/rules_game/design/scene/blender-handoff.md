# 第一夜洋楼：AI → Blender 高精度建模交接规范

> 用途：把经审定的平面、分镜和场景图转成可复核的 Blender 源文件与 目标引擎 候选导出物。
> 状态：生产交接草案；不代表场景已经建成、导入或在 目标引擎 中通过验证。
> 范围：第一夜的两层洋楼、院落、可见静态结构和静态陈设；动态玩法对象另行装配。

## 1. 生产前的唯一依据

- 先以《第一夜完整游玩流程》§3 的节点、邻接、门状态和观察位为功能依据。
- 平面尺寸未冻结时，先制作可编辑灰盒；不可从气氛图估算房间尺寸或新开门洞。
- 每个房间应有一张带尺寸、门窗编号、楼梯落点和观察位编号的正交图。
- 正交图和邻接表优先级高于透视概念图、AI 参考图和摄影参考。
- AI 参考图只表达材质、年代、光感和陈设密度，不能当作建筑测绘资料。
- 图中幻觉出的门、窗、壁炉、楼梯、走廊或额外房间一律不照抄。
- 若参考图与路线冲突，保留路线并在资产问题单中记录冲突，不自行改剧情流程。
- 建模前核对：F1–F10、S、U1–U8、O1–O6 的可达性和规定捷径。
- F6、F7、U4 可小型化并复用套件；不得借此删除必经门洞或固定地标。
- 不制作地下室、第二主楼梯、可游玩的街区或第二夜的室内空间。

## 2. 坐标、尺度与原点

- Blender 采用米制：1 Blender unit = 1 m，单位显示 Metric，长度 Metres。
- 世界轴固定为 X 向东、Y 向北、Z 向上；地面位于 Z=0。
- 正交总图北向朝 +Y，东向朝 +X；所有分场景沿用同一世界坐标，不各自旋转北向。
- 主楼、院落、门洞和观察位必须使用同一坐标原点，禁止拼接时以视觉对齐代替数值对齐。
- 每个房间壳体原点设在该房间布局矩形的西北角地面点；记录其全局 X/Y/Z。
- 独立道具原点设在合理接触或旋转点：落地物在底面中心，壁挂物在背面安装中心。
- 门扇原点设在铰链轴底部；窗帘杆原点设在杆中心；抽屉原点设在滑轨起点。
- 镜托原点设在固定安装中心；旧手镜为独立英雄道具，原点设在握柄几何中心。
- 以 1.70 m 成人眼高和约 0.45 m 坐高复核门把、桌面、窗台、楼梯和镜面高度。
- 常用室内门净高建议 2.00–2.10 m，门净宽建议 0.78–0.90 m；最终以正交图为准。
- 走廊、楼梯和门口须先通过玩家碰撞灰盒；装饰不能侵占既定通行净宽。
- 不要为“老洋楼感”压低门、梁或楼梯到不适合第一人称移动的尺度。

## 3. Blender 与 目标引擎 的边界

- `.blend` 是可编辑源文件，保留集合、命名、UV、材质节点和可复用部件。
- `.glb` 是候选交付物，只包含需要导入引擎的网格、嵌入贴图和必要物理轴动画。
- 导出前应用静态网格的 Rotation/Scale；保留按布局记录的 Location 和对象原点，不盲目执行 Apply All。不要靠对象级非均匀缩放隐藏尺寸问题。
- 不在导出前手动猜测 目标引擎 轴转换或整体旋转补偿。
- 用一个 1 m 轴向测试物导入当前 目标引擎 工程，核验朝向、比例、原点和法线后再批量导出。
- 在该实机导入核验前，目标引擎 的最终变换参数、导入选项和碰撞生成方式均标记“待测”。
- 每次导出附一份对象清单：源 `.blend`、目标 `.glb`、三角数、材质槽数、贴图列表和版本号。
- 源文件与导出物分目录保存；不可把唯一可编辑源文件替换为导出的 GLB。

## 4. 集合、对象与命名

- 顶层集合使用：`ENV_STATIC`、`ENV_DYNAMIC_REF`、`PROPS_STATIC`、`HERO_REF`、`COLLISION`、`MARKERS`、`LIGHT_REF`。
- `ENV_DYNAMIC_REF` 和 `HERO_REF` 仅作位置、尺寸和接口参考，默认不打包进静态房间壳。
- 静态房间壳命名：`room_<node_id>_shell`，例：`room_f2_shell`、`room_u6_shell`。
- 静态结构分件命名：`room_<node_id>_<floor|wall|ceiling|trim>_<nn>`。
- 静态陈设命名：`prop_<category>_<name>_<nn>`，例：`prop_furniture_sofa_01`。
- 动态门参考件命名：`dyn_door_<from>_<to>_<nn>`；门框属于静态壳，门扇不属于静态壳。
- 动态窗帘、灯、镜托、抽屉等参考件分别以 `dyn_curtain_`、`dyn_light_`、`dyn_mirror_stand_`、`dyn_drawer_` 开头。
- 旧手镜参考件命名：`hero_mirror_hand_01`；不得烘焙进楼梯壳或抽屉壳。
- 玩法道具参考件命名：`hero_<item>_<nn>`，例如钥匙圈、录音机、手电。
- 碰撞网格命名：`<object_name>-col`；简化凸包才用 `<object_name>-convcol`。
- 可选遮挡网格命名：`<object_name>-occ`；仅为性能测试需要时制作。
- 观察与交互定位点命名：`marker_<id>`，如 `marker_v1_mirror_view`。
- 禁止用材质名、物件名或集合名承载剧情状态、存档字段或规则判断。

## 5. 静态壳与动态玩法拆分

- 房间壳只收录地板、墙、天花、踢脚线、固定门框、固定窗框和不参与玩法的陈设。
- 所有门扇、插销、链条、窗帘、可开抽屉、开关、电话运动部件、镜子、门户、热点和 blocker 都由 目标引擎 装配。
- 建模可提供动态物件的低模参考和安装孔位，但不把它们合并进 `room_*_shell`。
- 门框与门扇间留出真实缝隙；门扇全开、半开、观察位均不得与墙或地面穿插。
- 需要开门的洞口须有完整门框、踢脚线收口和墙厚，不能以贴图洞或单面洞代替。
- 隐蔽面可减面，但从任一可达玩家位置、开门角度、镜景或反射可见的面必须存在。
- AI 常漏掉墙背、门框内侧、楼梯底面、窗洞侧壁和天花连接；导入前逐项补齐。
- 不用布料模拟、碎片模拟、流体或实时反射来完成第一夜必需事件。

## 6. 几何质量

- 所有可见硬表面保留小倒角，建议 1–5 mm；大木边或石材可按真实构件放大。
- 倒角后使用合理的 Auto Smooth / Weighted Normal 流程，消除不应有的黑边和梯度断裂。
- 平面墙体、地板和柜门不得因 AI 网格噪声出现波浪、重叠面、非流形孔或零面积三角形。
- 清理重复顶点、内部重叠面、翻面法线、悬空碎片和不可见但造成阴影的封闭体积。
- 楼梯台阶、门框、桌边、镜框等近视物体优先保持清晰轮廓，细节不靠百万面置换。
- 静态壳不超过 3k tris/房间；普通道具建议不超过 1.5k tris；手镜等英雄道具不超过 8k tris。
- 单个可见房间建议不超过 25k tris、8 个材质槽；可见层建议不超过 150k tris。
- 这些是第一夜的生产建议和验收上限，非已在目标硬件测得的帧率事实。

## 7. UV、贴图与材质

- 每个输出网格需要非重叠的 UV0；可平铺部件允许共享图集或 tile UV，但不能产生不可控拉伸。
- 室内默认目标约 256 px/m；镜框、电话等近读英雄面可约 512 px/m，需在测试场景校准。
- 纹理分辨率默认 512–1K；近距离可读英雄资产最多 2K；禁止 4K 作为默认方案。
- 共用墙漆、木地板、石材、金属和木饰面采用 tile/trim sheet，避免每房单独烘焙整张贴图。
- 可复用 trim 至少覆盖：踢脚线、门窗套、墙角、木线、窗台和柜体边条。
- PBR 贴图按 Base Color、Roughness、Normal、Metallic（仅金属）分通道；可使用 ORM 打包但须记录通道顺序。
- Base Color / Emissive 使用 sRGB；Roughness、Metallic、Normal、AO 与遮罩使用 Non-Color / Linear 数据。
- 法线使用切线空间 Normal，确认绿通道方向与目标导入器匹配后再批量输出。
- 玻璃、镜面和窗外不作为真实反射或透明效果的前提；其最终表现由 目标引擎 look-dev 测定。
- 同一材质族保持统一命名和参数，例如 `mat_wall_warm_01`、`mat_wood_dark_tile_01`。
- 禁止无授权品牌标志、可识别人脸、AI 水印、无法追溯来源的文字或随机二维码进入贴图。

## 8. 打包、复用与 LOD

- 导出 GLB 时嵌入所需贴图；不得依赖外链绝对路径、临时下载目录或作者机器的贴图缓存。
- 提交前在一台未装原贴图路径的环境中重新打开/导入，确认没有丢贴图。
- 每个房间壳优先复用住宅 Kit、后勤 Kit 和院落 Kit，不复制看似相同的墙、门框和柜体网格。
- 小型室内房间默认不制作 LOD；先控制基础面数、材质槽和可见性。
- 院落远景或反复出现的大型装饰可提供 LOD0/LOD1，LOD1 仅保留大轮廓和基础材质。
- LOD 切换距离、draw call、显存、贴图压缩、透明过绘和灯光方案均待 目标引擎 实机 profiling 后确定。
- 不把未测的 LightmapGI、体积雾或镜面反射写成必须启用的生产要求。

## 9. 每个 AI 产出进入 Blender 前的检查

- [ ] AI 图已标明仅为视觉参考，且有对应正交尺寸图和房间编号。
- [ ] 门窗、楼梯、走廊和院门逐一匹配已批准的邻接与开闭状态。
- [ ] 没有新增通路、隐藏房、夸张大堂、战场街景或第二夜可玩区域。
- [ ] 建筑比例符合 1.70 m 人尺度，通道可走，重点物体在合理高度。
- [ ] 可见面、门洞内侧、门框厚度、楼梯底面与墙背已补齐。
- [ ] 网格无非流形、穿插、重面、破洞、翻面、悬空碎屑或异常高密度区域。
- [ ] 门框、窗框、墙体、地板的接缝在相邻房间坐标中连续。
- [ ] UV 不重叠（允许的 tile/trim 共享除外），关键近读面没有明显拉伸。
- [ ] 材质通道、色彩空间、贴图尺寸和嵌入状态符合本规范。
- [ ] 动态对象、碰撞、marker 和静态壳已分集合、分命名、分导出。

## 10. 导出前与引擎验收清单

- [ ] `.blend` 可独立打开，所有依赖贴图已打包或位于项目受控目录。
- [ ] 每个 `room_<node_id>_shell` 有正确原点、米制尺寸和应用后的变换。
- [ ] GLB 只包含规定的静态壳或单一独立道具，不意外夹带灯光、相机、参考图或动态玩法物。
- [ ] 1 m 轴向测试物已在 目标引擎 实测；结果记录轴向、缩放、原点与法线是否正确。
- [ ] 玩家碰撞、门开合扫掠、楼梯往返、门框通行和观察位视线由灰盒或引擎测试确认。
- [ ] 关键镜景 V1–V3 的构图能看见需要比对的现代实体位置；镜面不需实时全场反射。
- [ ] 房间的三角数、材质槽、贴图数和可见层预算有实际统计；超标项有明确降本动作。
- [ ] 导入缺失时，目标引擎 灰盒回退仍可用；美术壳不能成为阻断路线的唯一条件。
- [ ] 导出、导入与测试结论分别记录，不能用静态检查代替 目标引擎 实机验证。

## 11. 交付包最小结构

```text
villa-night1/
  source/room_f2.blend
  source/kit_residential.blend
  export/room_f2.glb
  export/prop_furniture_sofa_01.glb
  docs/room_f2_orthographic.pdf
  docs/room_f2_export-manifest.md
```

- 每份 `export-manifest` 写明房间 ID、版本、坐标原点、尺寸、相邻开口、tris、材质槽、贴图及已知待测项。
- 任何改动门洞、墙体边界、楼梯位置、观察位或可见镜景的提交，都要附新旧正交对比并回查第一夜路线。
- 本规范只约束可生产和可验收的资产交接；剧情、规则、死亡条件和世界状态仍以流程设计文件为准。
