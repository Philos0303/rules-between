# 第一夜洋楼：米制总平面决定

本文件配套 `geometry.json`。它把第一夜流程的 25 个功能节点落到可共享墙、真实门洞和米制坐标上，供后续总图、分场景图和 Blender 建模使用。坐标基准、净空间和墙体偏移规则以 JSON 的 `metadata` 为准。

## 总体尺度与建筑性格

JSON 房间轮廓改为墙体中线，实际净尺寸由内隔墙向内扣 0.10 米、外墙向内扣 0.15 米后生成；此前的面积只可作为方案级估算，不能当作实测面积。这个规模可作为四客房、小型自助民宿成立，也保留了战前住宅被后期切分、加设后勤翼的痕迹。

主楼不做中轴对称：南侧是向前院打开的 L 形玄关，生活环在中部，厨房向西北伸出，狭窄后勤翼向东伸出。二层的电话厅、阳台和原主卧沿北侧连成一条可看见后院的带状空间；二号房被放在东北角，既能从短廊进入，也能观察后院晾衣杆。主楼梯位于玄关西侧，整个游戏只有它一处上下交通。

## 固定玩法邻接

以下邻接与 `../first-night.md` 第 3.2 节完全一致：

- 一楼生活环：F1—F2—F3—F4—F8—F1；F3—F5—F6 是厨房支路，F8—F7、F8—F9—F10 是后勤支路。
- 外圈：F5—O2—O3—O4—O5—F9—F8—F1；O5—O1 是可解锁捷径，O3—O6 是永久封闭的街角观察支路。
- 二楼：S—U1；U1 分别接 U2、U3、U4、U5、U6、U7；U6—U8—U5 构成绕开错位短廊的安全回路。

因此不改表线、里线、事件时间、死亡条件或物品门禁。场景建模时不得另开未定义的穿墙捷径。

## 外部空间的具体关系

O2 后院紧贴厨房北门，晾衣杆、厨房窗与旧遮光钉孔都在同一个视野内。O3 由后院东侧伸向北方，是一条约 2.5 米净宽的侧巷，排水沟沿其边缘持续通向 O4。O4 的墙中线包络为 7.0 米乘 5.0 米，树根和沟沿被放在正常出口一侧；假箭头门面位于另一侧墙面，不通往新地图。

O5 是东侧后勤小院，直接接洗衣间，并经一扇从内侧可拔插销的小门回到前院。O6 只是一段被施工围挡封住的街角视角。它应有明确可读的封闭物，不需要街区、车流或第二张户外地图。

## 对后续图像与建模的硬约束

- 房间多边形是墙体中线；相邻房间只生成一面共享墙。内隔墙厚 0.20 米，净空间从中线向内扣 0.10 米；外墙厚 0.30 米，净空间从中线向内扣 0.15 米。
- 每个 `openings` 条目已经给出门洞中心、净宽、净高和其所在共享边方向。除 S→U1 这个垂直交通连接外，所有门都落在两节点的共边上。
- 主楼梯总高 3.60 米，18 级 0.20 米踏步；每段 9 级、每段 8 个 0.25 米踏面，实际跑长 2.00 米。两跑沿 X 方向折返，分别占 y=0.80–1.95 和 y=2.05–3.20，转角平台为 1.30 米乘 2.40 米，楼梯净宽 1.15 米；二层楼板完整排除 x=-3.55 至 -0.25、y=0.80 至 3.20 的楼梯洞，洞边设 1.10 米栏杆。精确踏步、平台和上口坐标见 `geometry.json` 的 `stair` 字段。历史门墙改放在小前室北侧 y=4.40 的完整高度墙段，净高 2.15 米，不处于梯段、转台或上平台下。不得为路径方便追加服务梯或地下室。
- U2、U4、U7 南侧超过一层外墙的部分是有柱支撑的前门廊上方客房翼：按 JSON 所列五根 300 毫米砌体柱和前梁建造，不能制作成悬空房间。U8 是唯一允许挑出的开放阳台；其挑深 2.80 米，由一层生活区/厨房翼梁承托。
- 所有门洞的中心都精确落在两节点的共享墙中线上；`axis: X` 表示该共边为定 Y、门洞沿 X 展开，`axis: Y` 反之。只有 S→U1 是楼梯上口的垂直交通例外，其 z=3.60 落在同位的楼梯/二楼短廊堆叠中。窗洞中心 z 统一为 `room.z + sill + height / 2`，且只能落在外墙中线。
- U8 必须做成带栏杆和顶棚的开放阳台，不能封成第五间客房；其净宽约 4.5 米。U3、U6、U8 都需拥有朝 O2 后院的开窗或开口，保证晾衣杆能成为多点对照物。
- 历史入口只占 S 的一段可变化墙面和小观察位；不要挖出第二层地下空间，也不要先制作门后的第二夜室内体量。

## 为流程服务的场景重点

F1 门槛能够同时看到室内地板、门框和前院地面。F8 电箱与钥匙盒必须在明亮、可退回的位置。U6 电话桌与 U8 阳台门应在同一段空间内可互相辨认，让“声音源已停、方向却还在响”的判断可读。

F4 的旧柜位、U5 梳妆台背缘、S 楼梯墙补缝是三处固定镜面观察位。三者只需要局部旧景、实体磨损和短音效，不需要全屋战时版本。O4 的树与排水沟、F3 的窗帘与低位台灯则是室外/室内锚点，应被家具、植物和强装饰遮挡得最少。

## 采光、承托与静态核验

F2 四面都是室内关系，因此不设置伪装成外窗的开口；其采光来自 F1—F2 宽门上方的室内玻璃上亮。厨房、书房、二号房、电话厅、阳台和原主卧均能沿外墙朝 O2 后院获得实际视线；U2、U4 与 U7 朝南看 O1 前院，F10 朝东看 O5 后勤院。窗洞中心统一按“本层标高 + 窗台高 + 窗高的一半”记录。

U8 的 W07 是无玻璃的敞开阳台开口，0.55 米不是防坠高度；其外侧另设 1.10 米高栏杆，栏杆不得遮住朝 O2 的晾衣杆观察线。

楼梯上平台至电话厅 D25、以及一号房 D21，分别使用 1.45 米宽的实体楼板垫，按 1.00 米净通行宽控制。楼板洞北侧西半段的 0.40 米边带和南侧西半段的 0.20 米边带都必须从导航网格排除，不能被玩家误当作通往电话厅或一号房的捷径。

`../../tools/verify_geometry.ps1` 是此布局的静态核验脚本。它检查节点/开口数量、门洞共墙中线、同层正面积重叠、窗洞不落室内共墙或门洞、窗洞标高公式、垂直视线目标、楼梯踏步算术、历史墙净高，并用 0.10 米网格验证 U6 全平面由 S/F5/F6 的一层承托面覆盖。它不替代结构工程师的荷载计算，也不等同于 Blender 或游戏内试玩验收。
